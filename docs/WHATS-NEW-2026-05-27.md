# What's New — 2026-05-27 batch (agent-profile + team-engagement convergence)

Quick map of everything that changed in this batch so you know what to look for when
you bring the ACP up fresh, and what still needs a deploy/merge to be visible.

---

## ⚠️ READ FIRST — two gotchas for a fresh bring-up

1. **The new things live on FEATURE BRANCHES (not merged to default).** A "fresh from
   default" build shows the OLD behavior. To see the new things, build from the branches
   listed at the bottom.

2. **The D-rename is a COUPLED vibe-api + acp-api change.** The vibe-api now returns the
   agent-profile field as `identity_prompt`; the acp-api now reads `identity_prompt`. If a
   fresh ACP (new acp-api) talks to the **OLD cloud vibe-api** (still returns `identity_md`),
   **agent profiles come back EMPTY** — including "report as {agent}" personas.
   - ✅ Safe order: deploy the cloud **vibe-api + acp-api cut together**, then bring up the
     fresh ACP from the feature branches.
   - ❌ Don't run a new-acp-api build against an undeployed cloud vibe-api.

## New things (this session)

### 1. D-rename: `identity_md` → `identity_prompt` (agent profile field)
- **What:** the agent-profile wire field is now `identity_prompt`, matching the canonical
  doc-store key. Fixes the Workshop save round-trip (edits persist + propagate end-to-end).
- **Where:** vibe-api `4a2fa7200`, acp-api `c7cfefd`.
- **Status:** backend committed + build-clean. The Workshop FE profile-path flip is
  NextPert's at the cutover. Coupled deploy (see gotcha #2).
- **See it (post-deploy + FE flip):** edit an agent's identity in the Workshop → save →
  reload persists; "report as {agent}" boots the full saved persona.

### 2. 1:1 engage + swap-confirm 409 (one team per project; confirm to swap)
- **What:** a project holds exactly ONE active team. Engaging a *different* team REPLACES
  the current one and requires explicit confirm (`?confirm=true`). Without it →
  `409 ENGAGE_CONFIRM_REQUIRED` with the to-be-replaced team + the per-project tweaks that
  won't survive the swap.
- **Where:** vibe-api `c1a74ff04`.
- **Status:** backend committed + build-clean. NextPert's swap-confirm dialog is pre-built
  (dormant) and keys off this 409. Live after deploy + FE wiring.
- **See it (post-deploy):** engage a team on a project that already has one → confirm dialog
  listing the replaced team + lost tweaks.

### 3. teams-list admin consistency
- **What:** admins can now operate on ANY team (detail / update / delete / members /
  projects), not just teams they own. (Previously an admin could *list* every team but
  couldn't operate on one they didn't create.)
- **Where:** vibe-api `ad486bf3e`.
- **Status:** committed + build-clean. Live after deploy.

### 4. seq-drift-409 (IDP role creation)
- **What:** creating an IDP role now returns **409** (not an opaque 500, and not 400) on a
  primary-key sequence-drift conflict or a duplicate role name, with an actionable message.
  Deliberately does NOT silently auto-heal the sequence (that would mask a bad seed/restore).
- **Where:** IDP (PayEz.External.Id.Api) `0786a83cd`.
- **Status:** committed + build-clean. Live after the IDP deploy.

### 5. C — agent-onboarding skill reads the canonical doc-store
- **What:** the "report as {agent}" onboarding skill now reads identity from the ACP API
  (`/v1/agents/{name}/profile` → `data.profile`, the canonical doc-store) instead of the
  retired `vibe.global_vibe_agents` table. Agents boot with their REAL (backfilled) personas,
  and Workshop edits propagate to skill-onboarded agents.
- **Where:** acp-desktop `18e5d39` (`skills/agent-onboarding/SKILL.md`, port 3001 — matches
  the `/report` slash commands). QA-verified; the colonized `.kimi` copies were already on
  the API (port 3002, correct — left untouched).
- **Status:** committed, QA-verified. IN the fresh ACP if the reinstall includes this commit.
- **See it:** `report as DotNetPert` (etc.) → boots the full backfilled persona (verified
  ~3569 chars for BAPert). ⚠️ Same D-rename coupling — needs the cloud vibe-api returning
  `identity_prompt`, else the persona is empty.

### 6. `vibe.global_vibe_agents` retired
- **What:** the vestigial hard table (a stale parallel store of agent identities, never
  synced with the live doc-store) was dropped on prod. The doc-store is now the single
  source of truth.
- **Status:** prod dropped (CASCADE — only removed the table + the dead `agent_skills` FK;
  `agent_skills` data survived). dev-93 was already clean.

## Cutover checklist (DO IN ORDER — the deploy is coupled, both directions skew)

1. **Run the migration first:** `AKS/migrations/14_vibe_AddProjectTeamMemberEffortOverride.sql`
   against the vibe DB — BEFORE the vibe-api code, or EF errors on the missing column.
2. **Restore the acp-api D-rename:** `git -C E:\Repos\acp-api checkout wo1-auth-refresh-terminal-dead`
   — re-applies `c7cfefd` (`mapCloudProfile` reads `identity_prompt`).
   ⚠️ The acp-api is currently **DETACHED at `bf265ff`** (pre-D-rename, reads `identity_md`) for the
   FE-only restart so profiles populate against the still-old cloud. It MUST be back on `c7cfefd`
   for the cutover, or the new cloud (`identity_prompt`) + old acp-api (`identity_md`) = empty profiles.
3. **Deploy vibe-api + acp-api TOGETHER** (the D-rename lockstep). Shipping one side without the
   other = empty profiles in one skew direction or the other.
4. **Verified gate** (QA `cutover-gate.sh`): post-paired-deploy, assert agent profiles return FULL
   personas (len > ~1000 chars). Gate stays RED until it passes — catches the skew both directions
   (Aurum / BAPert 1388/1390). Don't hope the lockstep held; verify it.
